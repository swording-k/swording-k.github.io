# 三剑武器库与滚动背景设计规范

日期：2026-07-24  
状态：待用户复核  
适用页面：`index.html`

## 1. 目标

把首页右侧现有的单剑展示区改造成具有游戏武器库气质的三剑陈列台，并让用户选中的武器自然接管后续页面的电影式滚动背景。

该功能必须同时满足：

- 三件武器是用户真实喜爱的个人符号，而不是装饰性素材。
- 第一眼具有高级、沉稳、收藏级的武器陈列感，不做廉价游戏 UI。
- 保留个人网站现有文字、项目、联系方式和主要按钮。
- 桌面端交互流畅，移动端能够触控切换并主动降低效果复杂度。
- 不依赖后端，也不以粗糙实时 3D 模型换取形式上的“3D”。

## 2. 武器阵容

陈列台固定包含以下三件武器：

1. **狼首长剑**：权游影视质感的西式长剑，狼首剑柄、宽剑格、斑驳钢材；作为默认武器。
2. **越王勾践剑**：青铜材质、菱形暗纹、古雅而锋利，强调历史感和精密纹饰。
3. **和道一文字**：白色柄卷、简洁圆形刀镡、深色刀鞘，整体修长克制。

三件武器在页面中统一称为“藏剑”或“武器”，避免用严格的中式兵器分类限制日本刀。

## 3. 视觉方向

### 3.1 陈列台构图

- 主武器位于右侧展示区中央，完整轮廓可读，占展示区高度约 82%。
- 左右候选武器各占主武器视觉尺寸的约 62%–68%，分别向后倾斜，形成浅弧形陈列轨道。
- 主武器保持清晰、较高对比度和柔和边缘轮廓光。
- 候选武器降低至约 28%–38% 不透明度，亮度降低，不使用明显高斯模糊。
- 背景采用接近黑色的金属陈列空间、极弱暖金刻度和局部冷色反光；不加入宝箱、按钮框、属性数值或夸张粒子。
- 陈列台底部仅保留武器序号、名称与一行简短说明。

### 3.2 三件武器的差异

- 狼首长剑：冷灰钢、暗黑皮革、低饱和暖色旧化痕迹。
- 越王勾践剑：深青铜、黑绿氧化层、局部金色菱纹反光。
- 和道一文字：黑、白、冷银三色，光影更克制，突出修长剪影。

三件素材必须使用一致的摄影角度、透明背景、清晰边缘和相近的画布比例，避免切换时像三张来源不同的图片。

## 4. 交互设计

### 4.1 切换方式

用户可以通过以下方式切换主武器：

- 鼠标按住展示区后横向拖动。
- 在触控设备上横向滑动。
- 点击左右候选武器。
- 聚焦展示区后使用左右方向键。

拖动距离超过展示区宽度的 12%，或释放速度超过 0.45px/ms 时切换；否则回弹到原武器。

### 4.2 换位动画

- 三件武器沿浅弧形轨道换位，而不是水平直线轮播。
- 动画只改变 `transform`、`opacity` 和必要的 CSS 变量。
- 一次换位约 420–480ms，使用快速启动、柔和落位的缓动。
- 拖动过程中动画与指针一一对应；释放后吸附到最近的武器位。
- 连续输入期间不创建叠加动画，始终以最后一次有效选择为准。

### 4.3 滚动交接

- 用户从首页向下滚动时，两件候选武器先淡出。
- 当前主武器从陈列台的位置和尺寸连续过渡到固定的全页背景镜头。
- 交接过程中不得出现第二份武器闪现、瞬移或明显尺寸跳变。
- 进入内容区后，根据当前武器对应的镜头轨迹，依次展示柄部、护手/刀镡、主体纹理和尖端。
- 用户返回首页后恢复三剑陈列状态，且保留当前选择。

## 5. 状态与数据流

唯一状态为 `selectedWeaponId`，可取：

- `wolf-longsword`
- `goujian`
- `wado-ichimonji`

状态流为：

`拖动/点击/键盘选择 → 更新 selectedWeaponId → 更新三剑槽位 → 更新名称与说明 → 当前武器接管滚动背景`

选择结果以键名 `baojian:selected-weapon` 写入 `localStorage`。首次访问、存储不可用或存储值非法时，默认使用 `wolf-longsword`。

每件武器的数据包含：标识、名称、说明、图片路径、展示区构图参数和五段滚动镜头参数。交互控制器只消费数据，不在事件逻辑中硬编码某一把武器。

## 6. 前端结构

功能拆分为四个边界清晰的单元：

1. **武器数据模块**：维护三件武器的文案、资源和镜头配置。
2. **陈列台控制器**：处理拖动、点击、键盘、槽位换算与吸附动画。
3. **滚动交接控制器**：把当前主武器从首页坐标过渡到固定背景坐标。
4. **偏好与降级模块**：处理本地存储、移动端、低动态偏好和资源失败。

现有 `sword-integration-camera.mjs` 的插值思路继续使用，但改为按武器读取镜头配置。现有简历内容 DOM 不迁移、不重写。

## 7. 性能预算

- 继续使用纯前端 2.5D，不引入 Three.js、WebGL 模型或后端服务。
- 三件透明武器图优先使用 WebP；单张目标不超过 700KB，总资源目标不超过 2.1MB。
- 默认武器优先加载，另外两件在首屏空闲阶段预载。
- 页面运行时只保留三个武器图层，不复制大量 DOM。
- 拖动和滚动阶段只动画合成层属性，禁止动画修改 `top`、`left`、`width`、`height` 和大面积 `filter`。
- 不在滚动回调中反复读取布局；尺寸在初始化和窗口变化时缓存。
- GSAP ScrollTrigger 使用线性 scrub；陈列台换位使用独立的短时缓动。
- 桌面端以主流 Retina Mac 视觉流畅为基准，移动端关闭大范围光晕并降低武器尺寸。

## 8. 无障碍与降级

- 陈列台使用可聚焦的分组语义，当前武器通过可读文本和选中状态表达。
- 左右方向键可以完整完成选择，不依赖拖动。
- `prefers-reduced-motion: reduce` 下取消惯性与弧形飞行动画，改为短暂交叉淡入淡出。
- 屏幕宽度不超过 760px 时，侧边武器靠近主武器并减少透视深度，防止横向溢出。
- 非默认武器图片加载失败时，从可选序列中隐藏该武器并回退到狼首长剑；狼首长剑本身加载失败时隐藏电影背景，仅保留不受影响的简历内容。
- JavaScript 不可用时，首页显示静态狼首长剑，简历内容保持可访问。

## 9. 验收标准

### 视觉

- 首屏能同时辨认三件武器，中间主武器拥有明确视觉优先级。
- 三件武器切换时构图连续，不出现跳动、拉伸或透明边缘脏污。
- 任一武器成为背景后，内容仍可读，武器纹理不会被玻璃卡片完全模糊。

### 交互

- 鼠标拖动、触控滑动、点击和键盘均可切换。
- 当前选择能够控制后续滚动背景，并在返回首页后保持一致。
- 快速连续切换不会产生错位、重影或失去响应。

### 性能与稳定性

- 桌面端拖动和滚动无持续卡顿，动画不触发布局抖动。
- 移动端无横向页面滚动，触控手势不会阻止正常纵向浏览。
- 资源失败、存储不可用和低动态偏好均有可验证的降级行为。
- 原有简历文字、项目链接、联系方式和按钮通过回归测试。

## 10. 非目标

本阶段不包含：

- 制作或接入真正的 GLB/GLTF 三维模型。
- 鼠标控制实时三维灯光、反射或眼睛跟随效果。
- 武器属性面板、音效、战斗数值或游戏化升级系统。
- 修改个人网站现有简历信息、项目内容或信息架构。
- 自动生成未经视觉验收就直接上线的武器素材。

## 11. 实施顺序

1. 先制作并验收三件统一风格的透明武器素材。
2. 只在首页完成静态三槽构图，确认比例和视觉主次。
3. 加入拖动、点击、键盘与吸附切换。
4. 让当前选择接管现有滚动背景与镜头配置。
5. 完成桌面、移动端、低动态模式和资源失败验证。

任何后续视觉增强都必须建立在前三步已经验收的基础上，避免在素材或构图未确认时堆叠动效。
