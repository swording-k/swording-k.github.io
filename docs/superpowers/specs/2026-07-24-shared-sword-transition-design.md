# 展台宝剑到全站巨剑背景：整合设计

日期：2026-07-24  
分支：`codex/cinematic-sword-integration`

## 目标

在不改变原网站文案、项目、联系方式、区块顺序和导航行为的前提下，将首页右侧宝剑展示台中的银色狼首宝剑，连续过渡为贯穿全站的巨型电影感背景。用户继续向下滚动时，镜头依次展示剑柄、护手、剑身纹理和剑尖。

## 不变项

- `index.html` 中现有的个人介绍、能力、项目、生活和联系内容保持不变。
- 现有链接、二维码、按钮、导航锚点和可访问性语义保持不变。
- 页面继续采用自然纵向滚动，不改成强制翻页或五幕全屏叙事。
- 现有宝剑素材与旧实现不删除；本次改动可通过分支或提交回退。

## 视觉与交互

### 1. 首页展台

首页右侧展示台使用 `longclaw-screen-used-weathered-v2-transparent.png`。首屏仍然把它作为一件被陈列的作品：尺寸受展示台约束，展示台边框、说明和环境光保留。

### 2. 接管过渡

从首页滚动到第二屏的过程中，展示台宝剑与全局背景宝剑使用同一素材、同一纵横比和对齐锚点。两个图层短暂重合：

- 展台框架、说明文字和局部装饰逐渐淡出；
- 展台宝剑逐渐淡出；
- 已与其对齐的全局宝剑同步淡入、放大并移向第一段背景机位；
- 交接期间不出现瞬间跳位、换图或比例变化。

实现采用变换和透明度，不依赖付费 3D 模型，也不进行高开销的尺寸布局动画。

### 3. 全站镜头

过渡完成后，全局宝剑固定在视口后方。镜头进度由整页滚动位置与主要区块位置共同决定：

| 内容区块 | 默认镜头部位 |
| --- | --- |
| Hero → About | 狼首、剑柄与护手 |
| About | 护手与上段剑身 |
| Projects | 剑身纹理和中段刃面 |
| Life | 下段剑身 |
| Contact | 剑尖与完整轮廓收束 |

区块之间采用连续插值，不在锚点处硬切。桌面端增加轻微鼠标视差和金属扫光，但宝剑始终不接收指针事件。

### 4. 内容可读性

宝剑始终位于内容层后方。现有卡片不整体重做，只按需要调整背景透明度、边缘暗化和文字阴影。镜头水平位置与左右内容布局错开，避免关键剑柄压住正文。

### 5. 响应式与降级

- 桌面端保留完整接管过渡、纵向镜头旅行和轻微鼠标视差。
- 手机端缩短放大距离，将剑偏向右侧，并在正文后增加渐变暗部。
- `prefers-reduced-motion: reduce` 下取消滚动绑定和持续扫光，保留静态宝剑背景与全部内容。
- GSAP 或 ScrollTrigger 不可用时，网站仍可阅读、导航和点击。

## 代码边界

- `index.html`：只调整宝剑展示台/背景层所需的非内容标记和素材引用。
- `css/sword-background.css`：负责展台交接、背景层、响应式与降级样式。
- `js/main.js`：负责接管时间线、区块镜头映射、刷新与清理。
- 独立小样 `sword-cinematic.html` 保留，不作为正式首页入口。

## 测试与验收

### 自动测试

1. 在整合前记录首页内容保险清单：主要区块 ID、项目卡片数量、联系方式和关键链接。
2. 整合后断言保险清单完全一致。
3. 断言展台剑与背景剑引用同一透明素材。
4. 断言 GSAP 已注册 ScrollTrigger，滚动绑定使用线性 `ease: "none"`。
5. 断言手机端与减少动态效果模式存在明确降级。

### 真实浏览器验收

- 桌面首屏：宝剑正常处于右侧展示台，正文可读。
- Hero/About 交界：交接连续，没有跳位或闪烁。
- Projects 中段：镜头处于剑身，项目内容无遮挡。
- Contact 底部：镜头到达剑尖并完成收束。
- 手机首屏与中段：正文、按钮和标签均不被剑遮挡。

## 完成标准

只有在自动测试通过，并完成桌面、手机以及至少三个滚动位置的真实截图检查后，才可称为本地整合完成。分支创建、代码编写或静态测试通过均不等同于部署上线。
